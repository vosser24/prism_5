## Tactical lessons worth memory (candidates)

Two durable lessons surfaced this session:

1. **Parallel pgroup=review (T8 internal-consistency + T8b external-compliance) caught complementary findings.** T8 (internal consistency lens) found phase-count drift and commit-range overlap that an external Claude Code lens wouldn't have spotted. T8b (claude-master persona, Claude Code best-practices lens) found wrong-file misattributions (MEMORY.md cap enforcer file path) that an internal-consistency check wouldn't have spotted — *because both files exist and the misattribution is locally self-consistent within the CHANGELOG entry*. **Generalize:** whenever Phase K-style docs/release prep ships, both lenses are load-bearing. Dispatching them in parallel via `pgroup=review` paid off — they read shared artifacts but wrote independent findings; consolidation took one Edit pass.

2. **Phase J handoff carried one stale claim (untracked files) into Phase K.** Phase J said 4 files were untracked; T7's actual `git status` was clean. Reason: prior commit `a7656a5` (mid-Phase D) had already tracked them. Phase J's handoff was written before re-checking. **Generalize:** handoff "carry-forward backlog" lists should be re-verified by the next session before treating any item as work-to-do. T7 went from a task to a no-op in 30 seconds because I verified before acting. Worth a memory entry on handoff-doc hygiene.

Other session-specific observations that DON'T need memory (code carries them):
- Helper subcommand pattern (case statement in big switch) and exit-code convention (distinct codes for distinct failure modes) — captured in code.
- Sandboxable `--home` flag for testability — captured in test file as a precedent for future global-config-touching helpers.

## Strategic lessons (carry forward to v4.1 + future phases)

- **Subagent-driven scales to phase-end docs work.** Phase K had no test work in 5 of its 10 tasks (T2 / T3 / T4 / T5 / T10 are pure docs); subagent-driven would have added dispatch overhead without payoff. T-shape inline execution + dedicated review-only pgroup at the end captured the same review-loop catch rate (6 findings applied) at a fraction of the cost. **Heuristic for v4.1:** if a task is pure-prose with cross-file composition + a single source of truth, inline is fine; reserve subagent dispatch for tasks with implementation + tests + behavioral verification.

- **Plan-as-spec re-verification matters at session start, not just plan-write.** Phase K plan's T7 said "track 4 untracked files." When I verified at execution time, `git status` was clean. A re-verification step at the start of each task (before treating the plan as authority) catches stale assumptions cheaply. **Mitigation already applied:** Phase K plan included a "pre-execution hygiene" checklist that I treated as advisory — should make it a mandatory T0 in future phase plans.

- **Dog-food in T-shape mode is appropriate for execution+observation tasks, not for review.** T8 + T8b genuinely needed parallel fresh-context reviewers (each builds independent context, surfaces independent findings). T9 was execution against a testbed + log writing — I had all context, the steps were concrete commands, and dispatching would have added overhead. The Phase J handoff's "always run cross-implementation review" lesson does NOT mean "always dispatch every late-phase task" — it means the review pass is non-negotiable. The execution after the review can be inline if context is hot.
