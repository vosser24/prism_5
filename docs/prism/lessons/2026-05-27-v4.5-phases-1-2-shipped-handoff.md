## Outstanding concerns (carry to next session's Phase 5 review)

These are KNOWN, captured here for the cross-phase reviewer at T35. None are blocking; all can be deferred to v4.6.

1. **T12 verdict-flag lib hardcoding** — `tools/lib/prism-verdict-flag.mjs` is hardcoded to `.prism-phase-1-5-*` paths. The A1 hook (`hooks/prism-phase-0d-oob.mjs`) inlined its own `atomicWrite` helper instead of refactoring the lib. **Severity:** Minor. **Fix path:** refactor the lib to accept a `kind` parameter (e.g., `writeVerdict(kind, sha, payload)` writes to `.prism-phase-<kind>-verdicts-<sha>.json`); update both phase-0d and phase-1-5 hooks to call the unified lib; remove inlined helpers in phase-0d hook + the third copy of `atomicWrite` in `tools/prism-roster.mjs`. Estimate ~0.5d. **Defer to v4.6.**

2. **T13 Windows `claude` resolution** — `spawnSync('claude', ['-p', ...])` without `shell: true` does not resolve `.cmd` files on Windows. This affects BOTH `prism-phase-1-5-oob.mjs` (v4.4) AND `prism-phase-0d-oob.mjs` (v4.5). Production may silently fail to invoke `claude -p` on Windows installs where `claude` is a `.cmd` wrapper. **Severity:** Important (cross-platform regression risk). **Fix path:** either add `shell: true` (security implications — review carefully) or pre-resolve via `which`/`Get-Command` then spawn with absolute path. Add `PRISM_PHASE_0D_MOCK_VERDICT` and `PRISM_PHASE_1_5_MOCK_VERDICT` env vars for cross-platform behavioral tests. **Plan Task 38 manual smoke is critical** — it'll reveal whether production Windows actually has this issue or whether `claude` is a `.exe` in distributed installs.

3. **T15 SessionStart output format change** — `hooks/prism-session-start.mjs` was changed from plain-text stdout to JSON `{hookSpecificOutput:{additionalContext:...}}`. Per D005, SessionStart is a Context-only hook so JSON is the correct format. But: any downstream consumer (e.g., a shell script piping the hook output) would break. **Severity:** Important to verify in T38 smoke. **Fix path if needed:** add a `--legacy-text` flag or detect TTY vs structured-caller; default to JSON.

4. **Plan code-blocks have small drift risks** — the plan code blocks assumed certain export names and code shapes that differed from reality in 3 places (T11 reviewer prompt path constant didn't exist; T12 verdict-flag exports differed; T15 SessionStart output format wasn't what plan assumed). The implementer subagents handled each via DONE_WITH_CONCERNS. The plan is "directionally correct, locally adaptive" — fine for execution but be aware future Phase 3+ tasks may have similar minor mismatches. **Action:** subagents handle these well; just expect 1-2 DONE_WITH_CONCERNS per phase.
