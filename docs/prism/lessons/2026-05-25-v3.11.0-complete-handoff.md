## Tactical lessons (worth keeping)

- **ESM top-level `try` blocks have a TDZ trap with `const` declarations below them.** In `hooks/prism-agent-write-register.mjs`, the entry-point `try { /* uses isAgentPath, which closes over AGENT_RE */ }` ran during module evaluation before the `const AGENT_RE = ...` line below it. Function hoisting makes `isAgentPath` resolvable, but its body throws a TDZ error when it touches `AGENT_RE`. The outer `try { ... } catch { exit(0) }` swallowed the throw silently — 9 tests failed with zero stderr output. **Fix:** declare all top-level `const`s before any code that calls into the function graph. Or move the entry-point to a `main()` function that runs at the bottom of the file.

- **Sentinel/meta name collisions need a guardrail.** The health phase's user-meta key was `status` (`"green"/"yellow"/"red"`); the new v2 sentinel field is also `status`. The merge in `markPhaseCompleted` correctly overrode the user value with `"complete"`, but this only surfaced when a test asserted `phases.health.status === "green"`. Convention going forward: **user meta keys must be prefixed by phase** when they could overlap with sentinel fields (e.g., `health_status`, `health_checks_passed`).

- **Subprocess test harness > test frameworks for thin CLIs.** All six v3 test suites use `spawnSync` against ephemeral `mkdtemp` testbeds with hand-rolled pass/fail counters (~30 lines of harness). No `jest`/`mocha` dep; tests run in `<1s` total; failures show exact stdout+stderr. Reuse this pattern for v4.0 helpers.

- **Schema migration via "validate v1, then trust the migrator" beats "migrate first, validate as v2".** The v2 validator requires sentinel fields the v1 file doesn't have, so post-migration v2-validation must be skipped (or the migration trusted). The cleaner path was a small `validateStateV1` that only checks the v1 shape, runs *before* migration. After migration, the returned state already satisfies v2 by construction.

- **Atomic write via tempfile + `renameSync` is the right pattern across this codebase.** Reused in `prism-state.mjs` (state file), `prism-agent-write-register.mjs` (roster), and the existing `prism-memory-save-nudge.mjs` (v2.9.1 ATOMIC-WRITE-001). Always tempfile in the same directory so the rename is same-volume.

## Strategic lessons (for v4.0 decisions)

- **Anthropic 529 Overloaded events do happen.** This session lost ~40 minutes to consecutive 529s on subagent dispatch — six attempts spanning Task 1 review + Tasks 2/3 implementer + final review. Mitigation: the inline fallback path (subagent-driven-development skill → inline executing-plans) worked but cost extra context. For v4.0 work, **default to subagent-driven**, fall back inline only when the API is provably down (3+ consecutive 529s spanning >10 minutes).

- **Plan docs are worth the 15-min upfront cost.** `docs/prism/plans/2026-05-25-prism-sync.md` (Phase A.1) was the only sub-task with a written plan; the others were done from the D002/D004 specs directly. The plan made A.1 reviewable per-task and surfaced one design call (the `--smart-drift` warn-stub vs. ship-and-defer choice) early. For v4.0 Phase D (most complex remaining work), **write a plan first**.

- **"Deferred to vNext when telemetry supports" is a load-bearing pattern.** Three Phase C/D pieces were deliberately stubbed in v3.11.0 with the same rationale: `--smart-drift` for sync, `--fix` for validate-plugins, the bodies of `phase-plugin-validate` and `phase-project-master` in bootstrap. Each stub records what telemetry would justify making it real. **Don't lose track of these** — they're listed in D004's "Cuts" table plus the in-code stub notes.

- **The `/prism-clean` meta-loop is now real.** This handoff was still written manually because dog-fooding `/prism-clean` on the session that *built* `/prism-clean` is circular. Next session should run `/prism-clean` first thing — it's the first independent validation that the classifier UX produces the artifacts the spec promised.

## Notable design calls this session

- **`--smart-drift` ships as a warning-stub** that falls back to conservative — per D002 §5, opt-in EXPERIMENTAL until telemetry. Future work flips the warn to a real implementation.
- **Plugin-validate is NOT in the conservative sync loop.** The v2 bootstrap has it as a phase, but `/prism-sync` keeps its 4-phase conservative default (`structure, discovery, roster, health` + optional `identity`). Reason: plugin validation is its own command (`/prism-validate-plugins`), and conflating it with maintenance sync over-couples them.
- **Project-master phase defaults to skip** (D004 §3) — only runs with `--with-deep-dive`. The 7-phase planner explicitly excludes it without the flag.
- **roster.json scope is path-derived.** Hook writes to `~/.claude/agents/<name>.md` → global roster at `~/.claude/skills/prism-plan/references/roster.json`. Writes to `<project>/.claude/agents/<name>.md` → project-local roster next to the agent file. No magic; just `startsWith(<home>/.claude/agents/)`.
