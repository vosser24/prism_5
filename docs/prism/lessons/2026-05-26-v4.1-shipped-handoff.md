### v4.1 Phase C — telemetry auto-opt-in (commit `2531e12`)

Per [[2026-05-26-v4.1-roadmap]] §Phase C: 1.0d budget; closes Q10.

**Three-part wiring:**

1. **Consent prompt** in `/prism-bootstrap` health phase (Step 7b). AskUserQuestion-driven. Default = recommended-on. ONE-shot per machine; `asked_at` stamp prevents re-prompting. `--no-telemetry` flag pre-declines without prompting.

2. **Deterministic aggregator** at `tools/prism-telemetry-aggregate.mjs`. Honours the consent gate (exit 13 if no opt-in). Reads `~/.claude/.prism-routing.jsonl`, writes the rollup at `~/.claude/.prism-telemetry-rollup.json`. Surfaces tuning candidates: any guard accounting for ≥25% of denies AND ≥3 denies total.

3. **prism-updater consumption.** Step 3 (gap analysis) refreshes the rollup (dry-run) and lists tuning candidates as migration-plan candidates. Approval-gated like every other item — never auto-applies guard tuning.

**Bootstrap subcommands added:**
- `detect-telemetry-consent` → JSON: `{policy_path, policy_exists, opt_in, asked_at, parse_error}`
- `set-telemetry-consent on|off` → atomic write to `~/.claude/prism-policy.json` (preserves other top-level keys)

Both bypass the `.git/` guard via `TELEMETRY_CONSENT_COMMANDS` set (they operate on $HOME, not project root).

**Cross-project rollup deferred to v4.2.** Routing log entries don't carry a `project` field; adding one touches every guard hook (architectural change). Single-project today.

**Test surface:** 12 tests — consent read/write (6) + aggregate gate (2) + rollup math (2) + tuning candidates (1) + dry-run + force (2).

## Strategic lessons (carry forward to v4.2 + future phases)

- **The 4-phase v4.1 cadence (0 → A → B → C) worked.** Sequential, each phase ends with tests + sync + commit. The phase-boundary review gate was deferred to the end of the ladder (single mega-review on the full diff) rather than per-phase. For 1.0d phases that pattern is cheaper; for 1.5d phases (Phase B) it's a coin-flip — would be worth revisiting if a v4.2 phase grows beyond 1.5d.

- **Hook decision-control matrix continues to be load-bearing.** Every new hook in v4.1 was designed against the matrix BEFORE writing code — none of the v4.0 Phase F deferral pattern recurred. Worth memorializing as the standard hook-design protocol.

- **Pure-prose phases (Phase 0 + Phase B Q7/Q9 prose + Phase C consent flow) compose cleanly with implementation phases.** The phase boundary isn't "code vs docs" — it's "one set of audit questions vs another." Phase B mixed both and didn't fragment.

- **The flag-file pattern generalizes.** Phase A's `prism-flag-file.mjs` helper is now used by 5 distinct callers (clean-nudge / precompact-nudge / git-clean / prepush-review / SessionStart pickup). Same architecture would extend to v4.2's hard-gate review-done writer with zero changes — the helper is reusable as designed.
