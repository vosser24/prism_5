## One-sentence summary

v4.3 Phase B shipped: roster entries created by the agent-factory now carry `installed_via: "plugin" | "manual"` provenance (set from `$CLAUDE_PLUGIN_ROOT`), and `/prism-uninstall-cleanup` removes plugin-tagged agents (dir + flat file + roster entry, atomic) before `/plugin uninstall prism@PRISM`. Legacy entries without the field are treated as `"manual"` and never touched.

## What was re-scoped from the original handoff prediction

The v4.2 handoff predicted Phase B would switch agent **write target** on `$CLAUDE_PLUGIN_ROOT` (plugin-scoped path when running as plugin). Brainstorming surfaced this as wrong: `${CLAUDE_PLUGIN_ROOT}` is typically read-only cached payload, and factory-created agents are user content (data-loss risk on plugin update if owned by the plugin payload). The user picked the **pollution-free** framing: keep agents global, tag them with provenance. Cleanup is explicit via the new slash command — no SessionStart fallback detection.

## Strategic lessons captured this session

1. **Handoff predictions can be wrong about implementation shape, not just stale on outstanding work.** The v4.2 handoff predicted Phase B would switch write targets on `$CLAUDE_PLUGIN_ROOT`. Brainstorming surfaced that the path is read-only cached payload and the prediction was wrong. The user-driven re-framing (provenance tag, not path switch) was a 90% reduction in implementation surface. **Lesson:** brainstorm even when the handoff sounds prescriptive; verify the implementation shape, not just the goal.

2. **The "best in world Claude Code companion" target is the right north star.** When trade-offs surfaced (e.g., ship cleanup flow now vs defer), the user consistently chose to **over-deliver** for the friends-only distribution. Capture this in the project-v4-2-private-distribution memory if not already there.

3. **TDD red-first surfaced a Windows-bash test-portability concern** that would have shipped silently otherwise. The env-detection-smoke test was designed to spawn `bash` to verify the prose-instructed one-liner. On a Windows CI without bash, that test would have false-failed. The fix (graceful skip with a try-spawn-`echo ok`-first pattern) was added at implementation time, captured here for future tests that need to spawn non-Node interpreters.
