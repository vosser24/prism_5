## L4 — Run the FULL audit-runner each release, not just the unit suites
v5.2.10 caught that audit scenario `DSP-001` had been failing since **v5.2.4** (4 versions). v5.2.4 changed the dispatch-guard contract (read-only tools pass pre-dispatch) and updated the *unit* test (`test-prism-panel-deadlock`) but missed the audit-runner's **separate copy** of the old expectation. Releases ran the unit suites, not `prism-audit-runner.mjs`, so the 28/29 went unnoticed. **Lesson:** when a behavior contract changes, grep for *every* place that asserts it (unit tests AND `tests/v3/audit-scenarios.json`); and run `node tools/prism-audit-runner.mjs` as part of each ship, not just the `test-*.mjs` files.

## L4 — Live-only edits in a governed session MUST be reconciled to source
v5.2.4: a prior stress-test session edited two global hooks **directly in `~/.claude`** (read-only-allow + meta-screen). Those edits were untested, untracked, and would be **clobbered by the next `installer update`** (repo→`~/.claude`). **Lesson:** any hook/tool edit made live must be ported into the prism_3 source + TDD'd before the next install, or it silently vanishes. Diff `~/.claude/hooks/*` vs repo when resuming after a session that touched the live install.

## L4 — A fix can MASK another bug; removing it surfaces the latent one
v5.2.3 anchored the bare `ledger` stakes token (correct). That **exposed** that "design a new event-sourcing **architecture** from scratch" only ever panelled via the `ledger`-stakes accident — `PANEL_SIGNALS` didn't recognize `architecture` as a target noun. The TDD guard assertion ("genuine architecture must still panel") caught the regression v5.2.3 introduced, fixed in v5.2.4. **Lesson:** when removing an over-broad trigger, add a guard test that the *legitimate* cases it was accidentally covering still fire — the accident may have been load-bearing.

## L4 — Stale docs cause wrong AGENT behavior, not just human confusion
v5.2.9: three docs still described the safety gate as a blanket `rm -rf` block (pre-UAT-4). A project-master read them, believed `rm -rf ./frontend/dist` was hard-blocked, and worked around an **allowed** command. **Lesson:** docs that describe a guard/capability are *inputs to agents*. When behavior changes, fix every description (README was right; bootstrap/help/INSTALL were stale). Inaccurate capability docs are behavioral bugs.

## L4 — The project-master toolset must cover the full MAIN-LOOP surface
The project-master runs in the main loop and talks to the user, so a leaner subagent toolset is wrong for it. Took three iterations to get the baseline complete: v5.2.7 added `Skill` (master couldn't invoke brainstorming), v5.2.8 added `AskUserQuestion` (master tried `Skill(AskUserQuestion)` → error) + `TodoWrite`. **Lesson:** define an agent's toolset by its *role's documented needs* (deep-dive/clean/panel flows all call `AskUserQuestion`), not by copying a sibling agent that plays a different role. Make it a single named constant so it's consistent and testable.

## L3 — "Subagent" is the run mechanism; "disposable vs persistent" is the lifecycle
Clarified for the user: both ephemeral `general-purpose` workers AND `@agent-factory` specialists run *as subagents*. Disposable workers write no agent file → no `roster.json` entry → zero roster pollution (only a spend-ledger row for cost accounting). Persistent specialists are saved + reused. Use disposable for routine one-offs, hire persistent specialists for recurring domain expertise.

## L3 — Transcript pastes evade glyph-only paste detection
The recurring paste-over-fire class (ledger, plugins, panel) shares one root: `stripPastedContent` only removed lines *starting* with a transcript glyph, so interior synthesis prose survived into the user's "own words." v5.2.6 block-strips the whole transcript span (≥3 strong markers, first→last), excluding bare `>` so user quoting is safe. **Limitation noted:** a genuine request placed *between* transcript markers can be block-stripped from the panel decision (tier unaffected).
