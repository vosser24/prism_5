## Strategic lessons captured this ship

1. **TDD discipline maintained under time pressure.** Even with a complex multi-layer implementation, seeding the RED test first (Task 29) caught an off-by-one in the ratchet threshold calculation before it could silently ship with a wrong threshold.

2. **Plugin.json and CHANGELOG must move together.** The drift-guard test (test-plugin-manifest-drift.mjs) would fail if plugin.json bumped to 4.4.0 but CHANGELOG still said 4.3.0. Tasks 31+32 were committed atomically to avoid a broken intermediate state.

3. **prism-clean.mjs is a command-dispatch tool, not a lifecycle script.** The ratchet hook was added at the bottom of the file (runs after any subcommand), which is correct semantics — but future maintainers should note that every subcommand path triggers the ratchet. If this becomes a problem, a `--skip-ratchet` flag can be added.

4. **Windows path handling in `import.meta.url`.** On Windows, `new URL(import.meta.url).pathname` returns `/Y:/...` (leading slash + drive letter). The canonical PRISM convention — per the `feedback-windows-spawnsync-url-path` memory and used throughout `hooks/prism-session-start.mjs`, `hooks/prism-phase-1-5-oob.mjs`, etc. — is to use `fileURLToPath(import.meta.url)` from `node:url`. The Phase 4 `tools/prism-clean.mjs` originally used a regex `.replace(/^\/([A-Za-z]:)/, '$1')` hack; quality review flagged the divergence and the canonical fix shipped in commit `0c0014e1` before tag.
