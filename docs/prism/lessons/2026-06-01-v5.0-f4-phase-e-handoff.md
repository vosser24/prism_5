## ⚠️ Re-rank latency finding (the §11 senior-review residual — IMPORTANT, now measured)
A live spike (`tests/v3/rerank-spike.mjs`, runnable, NOT shipped — lives under tests/) measured raw
`claude -p` cold-start on this Windows box at **~20 s**, vs the **8 s** default re-rank budget. Result:
the default-on semantic re-rank **always times out and silently falls back to BM25** here — fallback
works flawlessly (no hang past 8 s, correct `(lexical only — timeout)` label, never throws), but the
"semantic" layer never actually engages on this platform at the default budget.

**Decision (human, 2026-06-01): KEEP the 8 s default + document.** Rationale: preserves the snappy-tool
invariant (design Challenge 4) and the mandatory silent-degrade; users who want re-rank to engage can
raise `PRISM_RECALL_RERANK_TIMEOUT_MS` (e.g. `25000`), accepting the ~20 s block per `--cross-project`
query. NOT changed in code. The §11 residual ("if quality doesn't beat BM25 the override can be
revisited") remains open as a quality question — the spike only proved the **latency** half; re-rank
**quality vs BM25** on a real multi-project corpus is still unvalidated (cold-start swamped the test).
