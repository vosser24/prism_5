## v4.1 sequenced plan (4 phases, all sequential per user preference)

Each phase ends with a dog-food walkthrough + handoff doc, same rhythm as Phases D/E/H/J/K.

### Phase 0 — D007 adjudication: agent-creator skill vs factory

**Goal:** lock the architecture before adding hooks that depend on agent-creation surface.
**Deliverable:** `docs/prism/adjudications/D007-agent-creator-vs-factory.md`.
**Scope:** Decide between (a) status quo — master-orchestrator does the gate inline, factory is sole creation surface; (b) add a thin `agent-creator` skill that captures the decision tree (use existing? skill-research mode? factory create mode?) and delegates. Default to (a) unless telemetry shows excess factory invocations.
**Side concern to resolve in D007:** the agent-factory Step 0 `git add -A` issue — adjudicate whether the factory should commit at all, or whether commits are the user's responsibility.
**Budget:** 0.3d. Pure prose; no code.

### Phase A — `prism-git-hygiene` hook bundle (Q3 + Q4)

**Goal:** target the two most catastrophic UX failure modes — lost uncommitted work + unreviewed push to main.
**Deliverables:**
- `hooks/prism-git-clean-nudge.mjs` (SessionEnd: writes `~/.claude/.prism-git-dirty-<project>` flag-file if `git status --porcelain` non-empty).
- SessionStart hook extension: reads the dirty flag → emits *"previous session left N uncommitted changes in `<files>`"* via `additionalContext`.
- `hooks/prism-prepush-review.mjs` (PreToolUse Bash filter `if: "Bash(git push *)"`): returns `permissionDecision: "ask"` + `additionalContext: "Run /code-review and /security-review first; then approve."` Nudge, not gate (per D005 / hook-API matrix — hooks can't synchronously invoke skills).
- Optional gate mode: if `~/.claude/.prism-review-done-<branch>` flag-file exists (written by a /code-review post-run hook), the push proceeds without ask. Enables opt-in hard gating.
- Tests: 3-5 cases per hook (sandbox `$HOME`, simulate `git status` states, verify exit codes + decision JSON).
- MIGRATION.md + /prism-help updated to surface the new hooks.
**Budget:** 1.0d.

### Phase B — SessionStart freshness sweep (Q1 + Q5 + Q6 + Q11 + Q7 + Q9)

**Goal:** one hook closes six audit questions. Throttled once-per-day; all nudges via legal `additionalContext`.
**Deliverables:**
- Extend `hooks/prism-session-start.mjs` with a `dailyFreshnessSweep()` step:
  - Diff `~/.claude/plugins/` cache vs current snapshot → nudge `/prism-index` if changed (Q1).
  - Read `~/.claude/update-log.json.last_check` → nudge `/prism-update` if >15d (Q6).
  - `stat ~/.claude/CLAUDE.md` mtime → nudge `/prism-discover --check-claude-chain` if >60d (Q6).
  - Scan `roster.json` for agents with `last_used` >90d → list candidates for `/prism-retire` (Q5).
  - Read `tools-registry.md` rotations since last sweep → surface newly-promoted tools (Q11).
- Add `domain_groups` block to `~/.claude/skills/prism-plan/references/roster.json` populated by `/prism-index` (Q9). `.md` files stay flat in `~/.claude/agents/` (Claude Code's loader requires it).
- New `/prism-roster --by-domain` view consuming `domain_groups`.
- README + `/prism-help` doc fix: 3-line paragraph explaining "factory writes globally; only `master-<slug>` is project-local" (Q7).
- Throttle: write `~/.claude/.prism-freshness-last.json` with timestamp; skip sweep if <24h.
- Tests: 6-8 cases (each nudge fires when condition met, none fire under throttle, none fire when all fresh).
**Budget:** 1.5d. Biggest payoff phase — closes 6 questions.

### Phase C — Telemetry auto-opt-in + cross-project rollup consumption (Q10)

**Goal:** foundation for evidence-based optimization. The 34-line `.prism-routing.jsonl` is symptom of "no one opts in" — fix at bootstrap.
**Deliverables:**
- `/prism-bootstrap` health phase adds an opt-in prompt: *"Enable PRISM telemetry? Local-only, no network. Aggregates routing decisions across projects for self-tuning. (Recommended.)"* Default = recommended-on with explicit user confirmation; writes `~/.claude/.prism-telemetry-consent.json`.
- `tools/prism-telemetry.mjs --aggregate` extended with cross-project comparison view (which guards fire most across all projects, which model tier is overused per project domain).
- `prism-updater` agent's protocol step 3 (gap analysis) extended to read `~/.claude/.prism-telemetry-rollup.json` and surface "guard A misfires 40% in projects of type X — consider tuning regex" as a migration-plan candidate.
- MIGRATION.md adds telemetry consent path + the `--no-telemetry` opt-out flag for `/prism-bootstrap`.
- Tests: 4-6 cases (consent prompt fires, opt-out respected, rollup consumes cross-project data, prism-updater surfaces tuning candidates).
**Budget:** 1.0d.
