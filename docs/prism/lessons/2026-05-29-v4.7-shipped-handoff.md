## Two bonus fixes found during the build (NOT in the original scope)

1. **Async-blind test harness** — `test-prism-freshness-sweep.mjs` and `test-prism-git-hygiene.mjs` ran async tests with a synchronous runner (`fn(); pass++`) that counted a pass before any post-`await` assertion executed. Converted both to an async-aware runner. This surfaced 4 hidden git-hygiene failures — all **test-environment artifacts** (HOME captured at flag-helper module-eval; a commitless temp repo breaking `git rev-parse --abbrev-ref HEAD`), **no production bugs**. Only these two suites had the pattern (verified by a precise scan of all 31 suites).
2. **Roster-lock first-creation crash** (pre-existing v4.6 bug, user approved fixing in v4.7) — `withRosterLock` opened `roster.json.lock` with `openSync(...,'wx')` but never `mkdir -p`'d the parent. First-ever agent auto-registration (no `skills/prism-plan/references/` dir) threw ENOENT → re-thrown → hook crashed → agent never registered. Fix: `mkdirSync(dirname(lockPath), {recursive:true})`. `test-prism-agent-write-register.mjs` 6/9 → 9/9. Had been masked by the async-blind harness + the unreliable-manual-counts lesson.
