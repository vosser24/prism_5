# D002 — v3.10.0 Hook Defaults, Drift Strategy, /prism-clean, and Behavioral Flaw Extensions

**Status:** Locked
**Date:** 2026-05-05
**Decision owner:** PRISM core
**Target release:** v3.10.0
**References:** D001-bootstrap-unification.md (parent design)

## Context

D001 specified the v3.10.0 bootstrap unification but left several defaults open. After adversarial panel review and user adjudication, this document locks the remaining decisions. Total v3.10.0 scope estimate: ~12 days focused work.

## Locked decisions

### 1. Release strategy
**Single-shot v3.10.0.** No v3.9.0 stopgap. User accepts higher build risk in exchange for one cohesive release.

### 2. Naming
- New bootstrap command: `/prism-bootstrap` (not `/prism-up` — avoids confusion with `/prism-update`)
- Existing `/prism-update` retained for PRISM-framework self-update (not renamed to `/prism-self-update`)
- `/prism-sync` retained for ongoing maintenance
- `/prism-clean` added as the user-controlled archival mechanism (see decision 6)
- `/prism-check` for read-only diagnostic (replaces /prism-health + /prism-audit + /prism-doctor)
- `/prism-agent` for create/retire/list (replaces /prism-app-expert + /prism-retire)
- `/prism-recommend` retained

### 3. Deprecated command policy
**HIDE the 8 subsumed commands.** They remain functional in code (do not remove) but are removed from `/prism-help` output and documentation. No deprecation warnings on stderr. Pragma's preference: minimize churn, avoid documentation rot of warnings that linger for releases.

Subsumed commands hidden: prism-init (legacy semantics), prism-discover (now phase of /prism-bootstrap), prism-roster --reconcile, prism-health, prism-audit, prism-audit-full, prism-doctor, prism-archive.

### 4. Auto-fire hooks (Option X — minimal)
**Only one auto-fire hook ships in v3.10.0:**
- **Agent-write hook** — ON by default. Fires when `~/.claude/agents/<name>/agent.md` is written; auto-registers in roster.json. Cost: ~50ms when fired (rare). User-visible: no.

**Removed entirely from v3.10.0 scope (NOT just default-off — removed):**
- **Stop hook** — removed. Sessions end deliberately; user runs `/prism-clean` before /exit.
- **PreCompact hook** — removed. Auto-compaction risk accepted; user can /prism-clean preemptively in long sessions if they choose.

The two removals save ~1 day of implementation and eliminate the false-positive noise risk + the visible mid-conversation latency of PreCompact.

**Trade-off accepted:** if user forgets to run `/prism-clean` before auto-compaction or sudden termination, session memory is lost. This is consistent with the design philosophy of explicit user control over silent automation.

**Companion change:** the existing `prism-memory-save-nudge.mjs` hook (turn 15, then every 5 turns) is updated to nudge `Run /prism-clean now to capture session state.` This makes the nudge actionable instead of vague. ~10 min of work.

### 5. Drift detection default
**Conservative (always re-scan).** Every `/prism-sync` re-runs full discovery (~2-3 min on a Nexus-3-class project). Reliable; handles all known edge cases (git checkout mtime reset, DB-only schema drift, mid-failure stale state).

**Smart mode opt-in** via `--smart-drift` flag, surfaced with `EXPERIMENTAL` warning. Promote to default in v3.12.0 if telemetry supports.

### 6. /prism-clean folded into v3.10.0
**Yes — added to v3.10.0 scope (~1 day).** Becomes the sole archival mechanism after Stop and PreCompact hooks were removed.

**Importance classification (5 levels):**
- L5 CRITICAL — auto-archive, no opt-out: panel adjudications (D###), agent deviation reports, security findings
- L4 HIGH — default selected: explicit architectural decisions, bug root causes with fix, new smoke procedures
- L3 MEDIUM — default unselected: refactor patterns reused 2+ times, performance numbers, cross-task gotchas
- L2 LOW — offered, unselected: per-task tactical lessons, drift findings, tool-usage notes
- L1 NOISE — auto-skipped: trivial Q&A, read-only exploration, routine edits

**Detection heuristics:**
- Panel ran in session → automatic L5
- Agent returned deviation report → automatic L5
- ≥1 PR or ≥1 commit produced → boost importance
- User said "lock this in" / "this is good" / "use again" → boost
- Multiple "remind me" / "what did we decide" prompts → flag as adjudication-needed
- Same root cause hit 2+ times → L3 (lessons-tactical)
- Session <10 min, no edits → automatic L1

**UX:** scan → present checklist by level → user reviews/edits → archive selected to docs/prism/{adjudications,deviations,lessons,smoke}/. Optional wrapper `/prism-bye` = `/prism-clean` + confirmation + /exit.

### 7. Behavioral flaw extensions in scope
The following retro flaws are addressed in v3.10.0:

| Flaw | Mechanism | Cost |
|------|-----------|------|
| #4 Panel bypass | Extend `prism-skill-trigger-guard.mjs` (fix existing regex parser bug first) to soft-block destructive tools when classification = NOVEL and no D### exists in current session or recent commits | 1 day |
| #5 Post-panel enforcement (partial) | Auto-record D### artifacts when panel concludes. Diff-check side (compare PR against locked decisions) deferred to v3.11.0. | 0.5 day |
| #7 External tools idle | "Compose-first canary" fires once per session if work pattern matches a Tier-1 tool capability and the tool wasn't invoked | 0.5 day |
| #13/#14 Self-diagnostic | (a) `.prism.db` canary — if no rows in 5 prompts, surface ONE loud warning; (b) mid-session invariant check every 20 prompts; (c) 1-line health summary at session start | 1 day |

**Total behavioral extension: ~3 days.** All piggyback on bootstrap-unification infrastructure; no new architecture required.

### 9. Test bed
**Throwaway project, NOT Nexus Reporting 3.** User will create a fresh testbed (e.g., `/tmp/prism-testbed-django/` or equivalent on Windows). Validation strategy:
- Golden-output diff harness comparing `/prism-bootstrap --dry-run` and `/prism-bootstrap` outputs to committed expected `.claude/` tree
- Crash-resume tests via SIGTERM after each phase state write
- PS 5.1 VM smoke test (non-ASCII paths, drive-different targets, Restricted execution policy)
- v3.8.9 → v3.10.0 migration test (detect-and-adopt synthesizes state file from legacy filesystem)
- 5-7 day soak on testbed before any contact with Nexus Reporting 3
