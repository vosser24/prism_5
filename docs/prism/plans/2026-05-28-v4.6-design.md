# v4.6 design — telemetry-driven calibration + data-quality + structured output + closeout

**Status:** Draft (pre-brainstorm; this is the scoping spec — run `/superpowers:brainstorming` before the implementation plan to pressure-test Layer 2's calibration model)
**Date:** 2026-05-28
**Captured by:** v4.5 ship session, forward-planning at user request
**Related:** [[2026-05-27-v4.5-design]] [[2026-05-27-v4.5-shipped-handoff]] [[2026-05-28-v5.0-roadmap]] [[feedback-cross-phase-review-pattern]] [[feedback-subagent-test-count-decay]] [[feedback-installer-manifest-coverage-cross-check]] [[feedback-pace-per-task-vs-phase-review]]

## One-sentence summary

v4.6 cashes in the telemetry layer v4.5 shipped as tooling-only: it first fixes the two broken event shapes v4.5 left behind (Layer 1 — `dispatch_cap` missing `actual_parallel`/`queue_depth`, `phase_0d_challenge` emitting constant `UNCLASSIFIED`), then builds the calibration engine (Layer 2 — the headline: a `--recommend-calibration` aggregator mode plus the four deferred telemetry-decision items, all shipped as **recommend-then-apply** so nothing silently auto-changes), adds the structured-output classifiers that feed both calibration and the reviewers (Layer 3 — validation classifier, failure-mode taxonomy, stakes detection), and closes out the tech-debt the v4.5 reviews flagged (Layer 4 — full roster-lock coverage, the verdict-flag `kind`-parameter refactor, the `--target` hook-command path gap, and Windows `claude` `.cmd` resolution) — ~15 items in 4 layers, ~6d, mirroring the v4.4/v4.5 cadence.

## Motivation

v4.5 deliberately shipped Layer 1 (telemetry) as **tooling only** — collect data, change no defaults — because no production telemetry existed at build time (install was deferred). v4.6 is where that data becomes decisions. But two things must be true first:

1. **The data must be usable.** v4.5's cross-phase reviewer found that `dispatch_cap` events omit `actual_parallel`/`queue_depth` (the `PostToolUse[Agent]` event doesn't expose sibling state) and `phase_0d_challenge` events emit `evidence_class: "UNCLASSIFIED"` for every challenge (nothing classifies them). A calibration engine reading those today would calibrate against noise. **Layer 1 of v4.6 fixes the event shapes before anything consumes them.**

2. **The calibration must not require a calendar gate.** v4.5 faced a "no production data at build time" paradox and resolved it by deferring decisions. v4.6 cannot defer forever, but it also can't assume 30 days of data exist (the user may install v4.5 the day before building v4.6). **Resolution: v4.6 ships the calibration *machinery* — an on-demand `--recommend-calibration` engine that proposes threshold changes from whatever data exists, for explicit user approval — rather than auto-tuning thresholds in the background.** This is buildable immediately, like v4.5's tooling was, and degrades gracefully when data is thin (it says "insufficient data; keeping defaults").

The remaining two layers ride along: structured-output classifiers (Layer 3) that turn free-text reviewer/validation signals into machine-readable taxonomies the calibration engine and reviewers can both consume, and a hygiene closeout (Layer 4) that pays down the specific tech-debt the v4.5 per-phase + cross-phase reviewers flagged.

Cut: **~15 items** across **4 layers**, ~6d implementation, ~4.5d wall-clock with parallel execution.

## Scope: the ~15 items

### Layer 1 — Telemetry data-quality (3 items, ~1d) — PREREQUISITE

The calibration engine in Layer 2 is only as good as the data. Fix the two shape bugs v4.5 shipped, plus add the coverage test that would have caught v4.5's manifest gaps.

| # | Item | Brief |
|---|---|---|
| 1 | **Q1** `dispatch_cap` enrichment | `hooks/prism-dispatch-cap.mjs` currently emits `{cap, subagent_type, description}`. Add `actual_parallel` + `queue_depth` by scanning on-disk `~/.claude/.prism-task-*/` dirs at fire time (count in-flight task dirs as a proxy for sibling dispatches). Bump `.prism-routing.jsonl` schema 3 → 4 (additive). |
| 2 | **Q2** `phase_0d_challenge` evidence-class enrichment | Two options, pick at brainstorm: (a) extend `hooks/prism-panel-guard.mjs` Path B to classify each `challenges[]` entry into the 6-class evidence taxonomy at panel-write time and write `evidence_class` back into panel.json, OR (b) have `hooks/prism-phase-0d-challenges.mjs` derive class from challenge text via a cheap regex/keyword classifier. Recommend (a) — single source of truth, reused by A1 reviewer + telemetry. |
| 3 | **Q3** installer manifest-coverage test | New `tests/v3/state/test-installer-coverage.mjs`: assert every `hooks/prism-*.mjs`, `tools/prism-*.mjs`, `tools/lib/prism-*.mjs`, `agents/*-reviewer*.md` on disk appears in `manifest.files[]`, AND every `manifest.files[].src` exists on disk. Closes the [[feedback-installer-manifest-coverage-cross-check]] gap that bit v4.5 three times. |

**Layer 1 invariant:** schema bumps are additive; v4.5 readers ignore new fields.

### Layer 2 — Calibration engine (5 items, ~2.5d — HEADLINE, LARGEST LAYER)

Each item ships as **recommend-then-apply**: the engine proposes, the user approves, then a writer applies. Nothing changes a default silently. This is the v4.6 thesis.

| # | Item | Brief |
|---|---|---|
| 4 | **K0** `--recommend-calibration` engine | Extend `tools/prism-telemetry-aggregate.mjs` with a `--recommend-calibration` mode: reads `.prism-routing.jsonl` + verdict logs, runs the rules from items #5-#8 against accumulated data, and prints a structured proposal (`{knob, current, recommended, evidence, confidence}[]`) plus a one-line apply command per recommendation. Degrades gracefully: emits `"insufficient data (n=X, need ≥Y); keeping current"` per knob when data is thin. NO writes. |
| 5 | **K1** parallel-cap retune rule | From `dispatch_cap` data (now enriched by Q1): if `actual_parallel` consistently hits `cap` with `queue_depth > 0` across ≥N dispatches, recommend raising the cap; if `actual_parallel` rarely approaches `cap`, recommend lowering. Outputs a recommendation only; apply via `prism-roster.mjs --set-dispatch-cap <n>` (new flag). |
| 6 | **K2** reviewer-agreement → escalate-model rule | From the B4 `--agreement` join (v4.5): if a spec's reviewer-agreement rate is below threshold (reviewer routinely overturns the master's verdict), recommend escalating that spec's `default_model`. Apply via the existing ratchet writer. |
| 7 | **K3** auto-clear `pending_upgrade` | When a spec's UN-CITED rate drops below 10% over the trailing window, recommend clearing its `pending_upgrade` flag (the v4.4 ratchet sets it at ≥30%; nothing clears it today). Apply via `prism-roster.mjs --clear-pending-upgrade <spec>`. |
| 8 | **K4** master-overrides-reviewer confirmation gate | When the master overrides an OOB reviewer's REJECTED verdict, require an explicit logged rationale. Telemetry from #4 reports the override rate; the gate itself is a small `prism-panel-guard.mjs` / session-start addition that surfaces "you overrode N reviewer verdicts last session — confirm intent". Recommend-then-apply: ships as advisory in v4.6, enforceable via `PRISM_OVERRIDE_GATE=strict`. |

**Layer 2 invariant:** the engine never writes a roster/policy change without a user-run apply command. Calibration is a *conversation*, not a daemon.

**Layer 2 risk note:** K0 is the keystone. If the data model proves too thin to produce meaningful recommendations even with synthetic fixtures, descope #5-#8 to "advisory print only" and ship K0 as a reporting tool — the calibration *decisions* then slip to v4.7. Decide at Phase 2 review.

### Layer 3 — Structured-output classifiers (3 items, ~1.5d)

These turn free-text signals into machine-readable taxonomies that both the calibration engine (Layer 2) and the reviewers consume.

| # | Item | Brief |
|---|---|---|
| 9 | **C1** validation classifier | A reusable classifier (`tools/lib/prism-validation-classify.mjs`) that tags a reviewer verdict body as `{valid, invalid, partial, unverifiable}` with reason. Used to make agreement-rate (K2) more precise than raw verdict-token matching. |
| 10 | **C2** failure-mode taxonomy | Structured taxonomy for *why* a verdict was UN-CITED or REJECTED (`missing_evidence`, `wrong_evidence_class`, `scope_drift`, `hallucinated_resource`, ...). Logged to verdict log; aggregated by K0 to show *which failure modes dominate* — the actionable signal for v5.0's A5 verdict-regression scanner. |
| 11 | **D1** stakes-detection classifier | Tier-classifier addition: detect high-stakes prompts (migrations, deletes, security, money) and bias them toward Opus + mandatory panel, independent of length-based tier floor. Feeds the existing tier router. |

**Layer 3 ↔ Layer 2 link:** C1 sharpens K2's agreement rate; C2 gives K0 a failure-mode breakdown; D1 is independent but rides the same classifier-infrastructure work.

### Layer 4 — Hygiene closeout (4 items, ~1d)

Pay down the specific tech-debt the v4.5 reviews flagged (recorded in v4.5 CHANGELOG known-limitations + the shipped-handoff).

| # | Item | Brief |
|---|---|---|
| 12 | **H1** roster-lock full coverage | Extend `withRosterLock()` to the 3 unwrapped mutation sites: `hooks/prism-agent-write-register.mjs`, `tools/prism-uninstall-cleanup.mjs`, `tools/prism-installer.mjs`. Closes the race v4.5 CHANGELOG documented. |
| 13 | **H2** `prism-verdict-flag.mjs` `kind` refactor | Refactor the lib to `writeVerdict(kind, sha, payload)` writing `.prism-phase-<kind>-verdicts-<sha>.json`; migrate both `prism-phase-0d-oob.mjs` (remove its inlined `atomicWrite`) and `prism-phase-1-5-oob.mjs` to the unified lib. Removes the 3rd copy of `atomicWrite` in `prism-roster.mjs` too. |
| 14 | **H3** `--target` hook-command path fix | **Found during v4.5 ship:** `--target` installs copy hook *files* to the target, but the merged `settings.json` hook *commands* still hardcode `~/.claude/...`, so a testbed install's hooks point at the laptop home and silently no-op. Fix: when `--target` is set and differs from `~/.claude`, rewrite the merged hook commands to reference the target's absolute hook paths (or introduce a `${PRISM_HOOK_ROOT}` token the exec wrapper resolves). Makes `--target` installs behaviorally live — the originally-intended use case. |
| 15 | **H4** Windows `claude` `.cmd` resolution | `spawnSync('claude', ['-p', ...])` without `shell:true` doesn't resolve `.cmd` on Windows; affects both OOB hooks. Pre-resolve via `Get-Command claude` / `which` then spawn the absolute path. Add `PRISM_PHASE_0D_MOCK_VERDICT` + `PRISM_PHASE_1_5_MOCK_VERDICT` env vars for cross-platform behavioral tests (carried over from the v4.5 Phases 1-2 handoff's open concern). |

### Items deferred to v4.7 / v5.0 (for the record)

**Deferred — coverage/hygiene (3):** E1 index-freshness proactive check, E2 tools-registry vs `roster.tools` sync, G1 pre-PROPOSAL staleness preview. Lower value; no telemetry dependency; can slot into any later minor.

**Deferred — structured output (1):** C3 one-click upgrade trigger. Depends on K3 (auto-clear) landing first to be safe.

**Deferred — installer cosmetics (2):** I3 banner alignment on long paths, I8 telemetry opt-in for install/upgrade success rates.

**Deferred — SCOPE GUARD heuristic upgrade:** the keyword-overlap heuristic stays advisory; a stronger heuristic (TF-IDF / embeddings / LLM judgment) is its own research bet — naturally lands alongside v5.0's F4 semantic index.

## Architecture

### Four-layer composition

```
v4.6 — four-layer build

Layer 1 — Telemetry data-quality (~1d, 3 items) — PREREQUISITE
  hooks/prism-dispatch-cap.mjs          — PATCH: Q1 actual_parallel + queue_depth (#1)
  hooks/prism-panel-guard.mjs           — PATCH: Q2 evidence_class at panel-write (#2)
  tests/v3/state/test-installer-coverage.mjs — NEW: Q3 manifest coverage (#3)
  .prism-routing.jsonl schema 3 → 4 (additive)

Layer 2 — Calibration engine (~2.5d, 5 items) — HEADLINE
  tools/prism-telemetry-aggregate.mjs   — EXT: K0 --recommend-calibration (#4)
  tools/prism-roster.mjs                — PATCH: --set-dispatch-cap, --clear-pending-upgrade (#5,#7)
  (K2 reuses ratchet writer; K4 small panel-guard/session-start addition)
  Recommend-then-apply. No silent default changes.

Layer 3 — Structured-output classifiers (~1.5d, 3 items)
  tools/lib/prism-validation-classify.mjs — NEW: C1 (#9)
  tools/lib/prism-failure-taxonomy.mjs     — NEW: C2 (#10)
  hooks/lib/prism-tier-classify.mjs        — PATCH: D1 stakes detection (#11)

Layer 4 — Hygiene closeout (~1d, 4 items)
  tools/lib/prism-roster-lock.mjs (callers) — H1 full coverage (#12)
  tools/lib/prism-verdict-flag.mjs          — H2 kind refactor (#13)
  tools/prism-installer.mjs                 — H3 --target hook-path fix (#14)
  hooks/prism-phase-0d-oob.mjs + phase-1-5  — H4 Windows .cmd resolution (#15)
```

### The recommend-then-apply calibration loop (Layer 2 keystone)

```
.prism-routing.jsonl  (enriched by Layer 1)
   verdict logs
        │
        ▼  user runs:  node tools/prism-telemetry-aggregate.mjs --recommend-calibration
        │
   K0 engine: K1/K2/K3/K4 rules evaluate accumulated data
        │
        ▼  prints proposal:
        │   [K1] dispatch_cap: 4 → 6   (evidence: 18/20 dispatches hit cap w/ queue; confidence: high)
        │       apply: node tools/prism-roster.mjs --set-dispatch-cap 6
        │   [K3] spec @foo pending_upgrade: clear  (UN-CITED 8% < 10% over 22 dispatches)
        │       apply: node tools/prism-roster.mjs --clear-pending-upgrade @foo
        │   [K2] spec @bar: insufficient data (n=3, need ≥15); keeping sonnet
        │
        ▼  USER reviews + runs the apply commands they agree with
        │
        ▼  roster.json / policy mutated (under withRosterLock, Layer 4 H1)
```

### Key design choices

| Choice | Decision | Rationale |
|---|---|---|
| Calibration cadence | On-demand user-run engine, NOT a background daemon | No silent default changes; user stays in the loop; resolves no-data paradox (degrades gracefully) |
| `dispatch_cap` sibling count | Proxy via on-disk `.prism-task-*/` dir count at fire time | Claude Code's `PostToolUse[Agent]` event doesn't expose true sibling state; the proxy is good enough for cap-utilization trends |
| evidence_class source | Classify at panel-write (Q2 option a) | Single source of truth; A1 reviewer + telemetry both read the same classified field |
| K4 override gate default | Advisory in v4.6; `PRISM_OVERRIDE_GATE=strict` to enforce | Same advisory-first posture v4.5 used for SCOPE GUARD; avoids blocking on a not-yet-validated rule |
| Schema versioning | `.prism-routing.jsonl` 3 → 4, additive only | v4.5 readers ignore unknown fields (same contract as v4.5's 2 → 3) |

## Testing strategy

**Unit / state tests (~40 new):** every new lib/hook + the calibration engine gets a test file. Calibration engine (K0) tested against **synthetic `.prism-routing.jsonl` fixtures** with known distributions (so it's testable with zero production data). Target: current 386 + ~40 = ~426.

**Synthetic-data calibration test:** a fixture with 20 dispatches all hitting cap + queue → assert K1 recommends a cap raise; a fixture with sparse data → assert K0 says "insufficient data". This proves the engine without needing real telemetry.

**Behavioral smoke:** after Layer 1 + 2, install to a live `~/.claude`, run a few real sessions, then `--recommend-calibration` and eyeball the proposal. (This is where the user's actual telemetry first matters — and why the v4.6 entry criteria want v4.5 installed.)

**Cross-phase review (mandatory, per [[feedback-cross-phase-review-pattern]]):** v4.5 proved this catches what per-phase reviewers can't. Run it after all 4 layers. Specifically check: does any Layer 2 apply-command actually mutate the right roster field? does Q2's evidence_class match what the A1 reviewer expects?

**Test counts ground-truthed by the controller, not subagents** (per [[feedback-subagent-test-count-decay]]).

## Risks and scope guards

| ID | Risk | Likelihood | Mitigation |
|---|---|---|---|
| R1 | **Calibration rules produce garbage on thin data** | High (if built before any install) | K0 degrades to "insufficient data; keeping defaults" below per-knob N thresholds; test with synthetic fixtures; descope #5-#8 to advisory-print if needed |
| R2 | **Q1 dispatch-dir proxy mis-counts siblings** | Medium | Document it as a proxy, not ground truth; K1 uses trend not absolute value; revisit if Claude Code exposes real sibling state |
| R3 | **H3 `--target` hook-path rewrite breaks default-path installs** | Medium | Only rewrite when `--target` set AND differs from `~/.claude`; default-path tests assert unchanged commands |
| R4 | **H2 verdict-flag refactor breaks v4.5 phase-0d/phase-1-5 verdict pickup** | Medium | Migrate both hooks + SessionStart pickup in the same commit; the O3 E2E test (v4.5) guards the pickup path — run it red-green |
| R5 | **K4 override gate annoys more than it helps** | Low | Advisory-only default; strict behind env var |
