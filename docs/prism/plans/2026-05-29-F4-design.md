## 0. Ground-truth correction to the roadmap (verified this session)

The roadmap (§F4) says "reuse the existing KB infra's embedding layer" and "recommend local embeddings." Both premises are **wrong on the facts** and the recommendation is hereby overturned:

1. **There is no embedding layer to reuse.** The "semantic" tier of the existing KB stack is **delegated wholesale to the hosted `notebooklm` CLI** (`tools/prism-kb-query.mjs` → `spawnSync('notebooklm', ['ask', ...])`). The *local* layer is **keyword routing** (`hooks/lib/prism-router.mjs`) + **domain classification** (`tools/prism-kb-domains.mjs`). No vector store, no embedding model, no ANN index exists anywhere in the repo.
2. **The existing index does not cover the F4 corpus.** `~/.claude/.prism-kb-index.json` (schema `version: 2`) indexes **resource descriptors only** — agents, commands, skills, rules. The knowledge artifacts F4 actually targets (adjudications, lessons, verdict logs, panel rationales, clean artifacts) are **currently unindexed**.
3. **A local-embeddings F4 is a NEW subsystem, not an extension.** It would require a vendored model file or native module (ONNX/transformers), violating the dep-free constraint and importing Windows native-module pain.

Therefore the central decision was re-opened from scratch (not inherited) and decided below.

**Verified facts grounding the decision:**
- Corpus volume is *small*: one project's knowledge corpus = ~1 MB across ~50 `.md` files (7 adjudications @ 66 KB, 24 lessons @ 260 KB, plans @ 734 KB). Across 10–20 projects this is single-digit MB / low-thousands of documents.
- Verdict logs are real and live at `~/.claude/.prism-phase-1-5-verdicts.jsonl` plus per-SHA `~/.claude/.prism-phase-<kind>-verdicts-<sha>.json` (`tools/lib/prism-verdict-flag.mjs`).
- `/prism-clean` writes its captured locked-design artifacts to **`docs/prism/adjudications/`** (the `D###` files) — confirmed at `tools/prism-clean.mjs:149` (`nextDNumber` → `join(root,'docs','prism','adjudications')`). So "clean artifacts" and "adjudications" are the **same source dir**; there is no separate clean-artifact glob.
- Confirmed corpus dirs on disk: `docs/prism/{adjudications,lessons,plans,smoke}`.
- Reusable infra confirmed: `prism-kb-indexer.mjs` (source-walking, `parseYamlFrontMatter`, `extractKeywords`, `walkFiles`), `prism-kb-domains.mjs` (pure 13-domain classifier), the autosync dirty-flag plumbing (`hooks/prism-kb-autosync.mjs` → `~/.claude/.prism-kb-dirty`), the recall tier-router shell (`tools/prism-recall.mjs`), and the E1 freshness seam (`checkKbIndexStale`, `hooks/lib/prism-freshness-sweep.mjs:231`).
- Manifest shape: 94 entries `{src,dst,executable}`; `remove_on_upgrade_patterns` already globs `tools/prism-*.mjs`, `tools/lib/prism-*.mjs`, `hooks/prism-*.mjs`, `hooks/lib/prism-*.mjs`.

## 1. LOCKED DECISION — retrieval backend

### Decision: **(e) Pure-lexical BM25 cross-project index in Node core AS THE BASE — PLUS (d) a default-on `claude -p` LLM re-rank as a required-but-degradable second stage that ships in the v5.0 MVP.**

One line: **Dep-free BM25 over the cross-project corpus is the base retriever; a default-on `claude -p` re-rank of the top-K lexical candidates is the shipped "semantic" layer — and it degrades silently to pure-BM25 ordering whenever the `claude` CLI is absent, slow, or errors.**

Two-sentence rationale: The corpus is small enough (low-thousands of short documents) that BM25 in pure Node core delivers good recall offline with zero new dependency, zero network, zero key — the only base that satisfies all four hard posture constraints simultaneously. The `claude -p` re-rank closes BM25's paraphrase gap using the subscription-auth generation channel PRISM already relies on (no new dep, no key, no embeddings endpoint needed), and because it is a **default-on-when-available** layer rather than a hard dependency, the offline/no-CLI path remains fully functional via BM25 ordering.

**Human override recorded:** the panel's original lean was "re-rank optional / `--rerank` opt-in / may slip to v5.0.x." The human **overrode** this: the re-rank is **default-on and ships in the MVP**. The critical invariant survives the override unchanged — *required means default-on-when-available, NOT a hard dependency*; the silent BM25 fallback is mandatory (§7, §8).

### The options, pressure-tested

| Opt | Backend | Verdict | Killing fact |
|---|---|---|---|
| (a) | Local embedding model (vendored / native ONNX) | **REJECTED** | Breaks dep-free; vendors a multi-MB binary; Windows native-module/ABI pain; no runtime exists. Disproportionate for a low-thousands-doc corpus. |
| (b) | Hosted embedding API | **REJECTED** | First mandatory network + first API-key dependency. Contradicts three posture statements ("No network. Ever.", subscription-only auth, no `ANTHROPIC_API_KEY`). There is no subscription embeddings endpoint — `claude -p` is generation, not embeddings. |
| (c) | NotebookLM-style optional hosted, silent-degrade | **REJECTED for the core**, retained only as the *existing* cloud tier | Precedented and degradable, but (i) it is a per-domain notebook keyed by the hosted service, not a cross-project provenance-tagged index; (ii) shipping cross-project *secrets* to a hosted notebook is a privacy escalation over today's resource-descriptor-only sync; (iii) it cannot be the **default** backend because the posture requires the default path to be fully offline. |
| (d) | `claude -p` as retriever/re-ranker | **ADOPTED as the default-on second stage** | No new dep, matches auth posture. Cannot be a *primary* retriever (can't scan thousands of docs/query — latency/cost/context-window ceiling), but is exactly right as a default-on re-rank of a small lexical candidate set (top-K, K≤20). |
| (e) | Pure-lexical BM25/TF-IDF, Node core | **ADOPTED as the base/offline retriever** | Fully dep-free + offline + no-key. The only base satisfying all four constraints. Corpus size makes "is lexical good enough as the floor?" answer **yes**. |

### How the "semantic" claim is honestly framed (post-override)

With the re-rank now default-on, the shipped default experience **is** semantically re-ranked — so user-facing prose says **"lexical retrieval + LLM re-rank"** (honest and accurate), and explicitly **NOT** "embeddings" or "vector search" (we ship neither). When the re-rank is unavailable, output is labeled "(lexical only — LLM re-rank unavailable)". We are still **not** shipping vector embeddings in v5.0; the architecture leaves a clean pluggable retriever seam so a future version could drop in a local embedding model behind the same query API without touching the corpus/schema/sync layers — a v5.x+ decision gated on a real recall-quality complaint, not a v5.0 commitment.

## 2. Adversarial challenges raised + resolutions

Per protocol, every advancing position survived ≥2 substantive challenges. The decisive three:

### Challenge 1 (vs. the BM25 base): "Lexical recall will silently miss paraphrased decisions — the whole point of F4 is 'have we solved something *like* this?', and BM25 can't match 'race condition on shutdown' to 'concurrent teardown deadlock'. You're shipping a keyword grep and calling it semantic."
**Resolution — UPHELD; and the human override directly strengthens the answer.** The challenge is correct that pure BM25 misses pure paraphrase. Three things blunt it: (1) PRISM's corpus is *highly* keyword-dense — adjudications/lessons/verdicts share a controlled vocabulary (the 13 domains, recurring failure-mode terms, file/flag names), so lexical overlap is much higher than in open-domain prose; (2) the **default-on `claude -p` re-rank (stage 2)** is the designed answer to exactly the paraphrase gap — it reads the top-K lexical candidates and re-ranks/synthesizes semantically, and because the human promoted it to default-on, the *typical* user experience is semantically re-ranked, not bare lexical; (3) a **query-expansion** preprocessing pass (domain-classifier-driven term expansion reusing `prism-kb-domains.mjs`) widens the lexical stage beyond literal tokens so the candidate set handed to the re-ranker already contains paraphrase-adjacent hits. Net: the semantic promise is met by the default-on stage 2; the BM25-only fallback is honestly labeled.

### Challenge 2 (vs. rejecting (a)/(b)): "You're letting the dep-free dogma defeat the feature. A 20–80 MB ONNX MiniLM is a one-time vendored cost and gives real embeddings offline with no key — that satisfies privacy AND no-network. You rejected the only option that delivers the actual headline feature."
**Resolution — REJECTION HELD.** Three rebuttals: (1) **dep-free is not dogma, it is the installer's load-bearing invariant** — the whole installer architecture ([[feedback-installer-architecture-pattern]]) is "Node core + thin shell wrappers + JSON manifests," and a native ONNX runtime is a per-platform binary with ABI/Windows-SMB/antivirus failure surfaces that the dep-free posture exists specifically to avoid; (2) **the cost/benefit is upside-down at this corpus size** — embeddings earn their keep at 10^5–10^6 docs; at 10^3 short docs BM25's recall gap is small and the default-on `claude -p` re-rank closes most of it; (3) **it is not rejected forever** — the pluggable retriever seam (§3, §6) means a vendored local embedder can land in v5.x behind the same API the moment a real recall complaint justifies the binary weight. We are deferring a heavy dependency, not foreclosing it.

### Challenge 3 (vs. the cross-project premise itself): "Cross-project surfacing is a *leak*, not a feature. Project A is a client's private healthcare repo; project B is a side project. F4 will surface A's adjudication text — possibly containing secrets, client names, PHI — into B's session. You've designed a cross-tenant data-exfil path and bolted privacy on as item 4."
**Resolution — UPHELD; it reshaped the privacy model (see §4), now sharpened by the per-corpus-type decision.** This is the single most important challenge and it forced privacy from "item 4" to a **first-class default-deny design**. With the human's **per-corpus-type opt-in** decision, the model is now finer-grained than originally proposed: a project shares *specific corpus types* (e.g. lessons + plans) while **withholding others** (e.g. client-specific adjudications) — directly answering the "A's adjudication text leaks" scenario by letting a project share its generic lessons but never its client-named adjudications. Resolutions baked in: (1) **per-corpus-type opt-in** via `.prism-kb-share.json` listing shared types (default = nothing shared); (2) **opt-in per consumer** — `--cross-project` is an explicit flag, never default recall; (3) **mandatory provenance** on every entry; (4) **secrets pre-scan + descriptor-not-body storage** — the global index holds metadata + lexical postings, never verbatim prose, with the body fetched lazily from the source path only for authorized consumers.

### Challenge 4 (NEW — vs. the default-on re-rank override): "Default-on `claude -p` puts a model round-trip on the hot path of an interactive command. `/prism-recall` was a sub-second local lookup; now every cross-project query blocks on `claude -p` latency (seconds), and a slow/hung CLI freezes the user. You traded a snappy tool for a laggy one."
**Resolution — UPHELD; it forced the explicit cost/latency + timeout policy in §7/§8.** The override is sound *only* if the hot-path cost is bounded and the fallback is instant. Baked in: (1) the re-rank fires **only** under the explicit `--cross-project` flag — the default 3-tier recall is untouched and stays sub-second, so the latency only attaches to a query the user explicitly opted into; (2) a **hard per-query timeout** (default 8s, configurable via `PRISM_RECALL_RERANK_TIMEOUT_MS`) on the `claude -p` spawn — on timeout/error/non-zero exit, recall **returns the BM25 ordering immediately**, labeled "(lexical only — re-rank timed out)"; (3) bounded input — only top-K (K≤20) descriptors, never bodies, sent via stdin (tempfile when >32 KB per the Windows arg rule); (4) the BM25 stage-1 result is computed and held *before* the re-rank spawn, so fallback is a zero-cost return of an already-materialized list, never a re-query. This converts the override's risk into a bounded, always-recoverable cost.

### Other challenges logged (resolved without changing the decision)
- *"SQLite (`.prism.db`) is right there — use it for the index."* → `.prism.db` is **telemetry only** by deliberate separation; co-mingling knowledge would entangle the telemetry schema/migrations with knowledge, and the lexical postings are tiny. Knowledge index stays JSON/sharded under `~/.claude/.prism-kb/` (§6). SQLite reconsidered only if corpus crosses ~10^4 docs.
- *"Freshness will rot exactly like the resource index did (E1 was deferred once already)."* → F4 extends the **same** E1 `checkKbIndexStale` seam rather than inventing a parallel one (§5), and absorbs the v4.6-deferred cross-project freshness item explicitly.
- *"Default-on re-rank makes test runs flaky / network-coupled."* → Tests must inject a stub `claude` runner and assert BOTH paths (re-rank present → re-ranked order; re-rank absent/timeout → BM25 order). No test depends on a live `claude` CLI. (§10)

## 3. LOCKED — corpus, per-entry schema, index schema, provenance

### Corpus (exact source dirs, per indexed project)
Indexed per the **per-corpus-type** opt-in (§4) — a project's `.prism-kb-share.json` enumerates which of these types it shares:
- `docs/prism/adjudications/*.md` — type **`adjudication`**. **NOTE:** `/prism-clean` artifacts are written here (`prism-clean.mjs:149`), so `adjudication` IS the clean-artifact corpus — there is no separate `clean-artifact` type or glob.
- `docs/prism/lessons/*.md` — type **`lesson`**
- `docs/prism/plans/*.md` — type **`plan`** (DESIGN/ROADMAP knowledge)
- Panel rationales: `tasks/workspace/**/panel.json` + `0d`/`1.5` rationale artifacts where present — type **`panel-rationale`**
- `~/.claude/.prism-phase-1-5-verdicts.jsonl` + per-SHA `~/.claude/.prism-phase-*-verdicts-*.json` — type **`verdict`**. **EXEMPT from per-corpus-type opt-in** — these are home-global PRISM-internal review-quality telemetry, not project-attributed, and A5 requires them. They are **always included** regardless of any project's share marker. Tagged `type:verdict` with originating-project provenance where the SHA/log carries it, so A5 can scope.

The four shareable types are `adjudication`, `lesson`, `plan`, `panel-rationale`. The fifth (`verdict`) is always-on and home-global.

**NOT in MVP corpus:** raw source code, arbitrary repo files, `node_modules`, anything outside the enumerated dirs.

### Per-entry schema (global descriptor — NO verbatim secret-bearing body)
```
{
  "id": "<project_id>:<type>:<slug>",        // globally unique, provenance-prefixed
  "type": "adjudication|lesson|plan|panel-rationale|verdict",
  "project_id": "<stable hash of project root realpath>" | "GLOBAL",   // GLOBAL for verdict logs
  "project_label": "<human dir name, for display>" | "(home-global)",
  "source_path": "<absolute path on the originating machine>",
  "title": "<frontmatter name or first heading>",
  "description": "<frontmatter description, bounded>",
  "domain": "<one of 13, via prism-kb-domains.classifyEntry>",
  "domain_confidence": <num>,
  "keywords_top": ["..."],                    // extractKeywords reuse
  "postings": { "<term>": <tf> },             // BM25 term frequencies (bounded vocab)
  "body_bytes": <int>,
  "source_mtime_sec": <int>,
  "indexed_at": "<iso>",
  "redacted": <bool>                          // true if secret-scan stripped/blocked content
}
```
Body text is **not** copied into the global store. The BM25 postings are derived term-frequency counts (a bag-of-words footprint), not reconstructable prose. Full body is read lazily from `source_path` at recall time, only for authorized consumers, only if the file still exists locally.

### Index schema (global)
```
{
  "version": 1,                               // F4 schema, independent of resource-index version:2
  "kind": "prism-kb-knowledge",               // distinguishes from the resource-descriptor index
  "built_at": "<iso>",
  "machine_id": "<stable host id>",           // forward-compat for later multi-machine sync (§6); single value in MVP
  "source_mtime_max": <int>,                  // for E1-seam staleness (same mechanic as resource index)
  "projects": { "<project_id>": { "label","root","shared_types":[...],"shared_at","entry_count" } },
  "df": { "<term>": <document_frequency> },   // for IDF
  "doc_count": <int>,
  "entries": [ <per-entry schema> ]           // OR sharded: see §6
}
```
`shared_types` per project records the per-corpus-type opt-in; `machine_id` is written now (single-machine MVP) purely so a later cross-machine merge has provenance to disambiguate — it does NOT enable sync in v5.0 (§6, §9).

## 4. LOCKED — privacy / provenance model (DEFAULT-DENY, per-corpus-type, first-class)

This is the controlling constraint, not an afterthought (Challenges 3 & 4).

1. **Default-deny, per-corpus-type inclusion.** A project contributes to the cross-project index **only** for the corpus types it explicitly lists in its root `.prism-kb-share.json`. Schema:
   ```
   { "version": 1, "shared_types": ["lesson","plan"], "shared_at": "<iso>" }
   ```
   No marker → nothing shared. Marker present but a type omitted → that type is withheld (e.g. share `lesson`+`plan`, withhold `adjudication` because adjudications may carry client specifics). The four shareable types: `adjudication`, `lesson`, `plan`, `panel-rationale`.
2. **Verdict logs are the one exemption.** `type:verdict` is home-global PRISM-internal telemetry, not project-attributed; it is **always indexed** independent of any `.prism-kb-share.json`. Rationale: it is PRISM's own review-quality data, low secret risk, and A5 needs it. This exemption is explicit and intentional (decision #3).
3. **Default-deny consumption.** Cross-project results surface **only** under the explicit `--cross-project` flag. The 3-tier default recall is unchanged and never reaches across projects.
4. **Mandatory provenance.** Every cross-project hit is labeled with `project_label` + `source_path` (verdicts labeled `(home-global)`); the consumer always knows the origin and can exclude projects. No anonymous cross-project content.
5. **Secrets defense-in-depth.** (a) Index-time secret pre-scan: entries matching secret/credential patterns are either redacted (`redacted:true`, postings stripped of secret tokens) or skipped; (b) the global store holds **descriptors + derived postings, not verbatim bodies**, so a leak of the index file does not leak prose secrets; (c) lazy body read happens locally on the consuming machine against the live source file — bodies never persist in the shared store; (d) the same secret pre-scan applies to descriptors sent to `claude -p` for re-rank (the re-rank receives only descriptors that already passed the scan).
6. **Redaction is conservative.** When secret-scan is uncertain, redact (fail closed). A redacted entry is still discoverable by domain/title but its body is gated.
7. **No hosted egress by default.** The MVP default path is fully local *except* the explicit, opt-in `--cross-project` re-rank, which sends only secret-scanned, body-free descriptors to `claude -p` over the existing subscription-auth channel — the same channel PRISM already uses for generation, not a new egress surface. (The legacy NotebookLM tier is unchanged and out of F4's scope.)

## 6. LOCKED — storage layout + migration/coexistence (single-machine; sync-compatible later)

- **New root:** `~/.claude/.prism-kb/` (a directory, distinct from the existing flat `~/.claude/.prism-kb-index.json`).
  - `~/.claude/.prism-kb/knowledge-index.json` — the global knowledge index (§3 schema, `version:1`, `kind:"prism-kb-knowledge"`).
  - **Sharding rule:** single JSON while `doc_count ≤ ~2000`; shard by `project_id` into `~/.claude/.prism-kb/shards/<project_id>.json` + a thin `manifest.json` once above that. Start single-file; the schema's `projects` map + per-entry `project_id` make sharding a pure storage refactor with no schema break. (Sharding threshold is a tuning constant.)
- **Multi-machine: explicit NON-GOAL for v5.0, but layout must not preclude it (decision #4).** MVP reads/writes only the local `~/.claude/`. To keep a later cross-machine sync cheap and non-breaking: (i) every entry already carries `project_id` (realpath hash) + the index carries `machine_id`, so two machines' indexes could be merged with provenance preserved; (ii) the per-`project_id` shard layout means a future sync could rsync/merge shard files rather than reconcile one monolith. **No sync code, no shared location, no network path ships in v5.0** — this is purely a "don't paint ourselves into a corner" constraint on the schema/layout.
- **Coexistence, not migration.** The existing `~/.claude/.prism-kb-index.json` (resource descriptors, `version:2`) is **untouched and unmoved**. F4 adds a *parallel* knowledge index. The `kind` field disambiguates. No migration of the resource index is performed or required.
- **Format = JSON** (dep-free, matches the existing posture). SQLite explicitly rejected for knowledge (telemetry-only separation, §2 challenge log).
- **Windows/SMB:** all writes via Node `writeFileSync` (atomic-write-then-rename pattern already used), never PowerShell redirection; paths via `fileURLToPath`/`pathToFileURL`.

## 7. LOCKED — query surface (`/prism-recall --cross-project`)

- **New flag `--cross-project`** on `tools/prism-recall.mjs`. Default behavior (the 3-tier classifier) is **unchanged** and stays a sub-second local lookup.
- **Composition with the 3 tiers:** `--cross-project` augments **Tier 1 (semantic)** only. Tiers 2 (state) and 3 (analytical) are unaffected. When `--cross-project` is set and the classifier picks Tier 1, recall runs:
  1. **Stage 1 — BM25 (always, fast, local):** query expansion → BM25 over the global knowledge index → ranked candidates with provenance. This result is fully materialized and held before stage 2 spawns.
  2. **Stage 2 — `claude -p` re-rank (DEFAULT-ON when CLI available):** pass top-K (K≤20) secret-scanned, body-free descriptors via stdin to `claude -p` for semantic re-rank/synthesis. **Bounded + degradable:**
     - Hard timeout: default **8000 ms**, override via `PRISM_RECALL_RERANK_TIMEOUT_MS`.
     - Disable switches: absent `claude` CLI, `PRISM_RECALL_RERANK=off`, or `--no-rerank` → skip stage 2 entirely.
     - On timeout / non-zero exit / parse failure / spawn error → **return the already-held BM25 ordering**, labeled "(lexical only — re-rank unavailable/timed out)". Never blocks, never throws to the user.
     - Payloads >32 KB → tempfile path, not argv (Windows ENAMETOOLONG rule [[feedback-windows-cli-test-args]]).
- **Output labeling (honest framing, §1):** re-ranked results labeled "(LLM re-ranked)"; fallback labeled "(lexical only — …)". Never "embeddings"/"vector".
- **Output fields:** ranked list with `project_label`, `type`, `title`, `source_path`, and snippet (lazily read, authorized only).
- **New management actions:** `/prism-recall --share-project [types…]` writes/updates `.prism-kb-share.json` (defaults to all four shareable types if none specified; explicit list for per-type control); `--unshare-project` removes it.

## 8. LOCKED — opt-in posture, cost ceiling, degradation

- **Opt-in at every layer:** per-corpus-type inclusion (§4.1), explicit `--cross-project` consumption (§4.3), and the re-rank confined to that explicit flag. F4 is inert for default recall.
- **Re-rank cost/latency budget (now on the explicit hot path):** at most one `claude -p` spawn per `--cross-project` query; input bounded to K≤20 body-free descriptors; **8s hard timeout** with instant BM25 fallback; no re-query on fallback (the BM25 list is pre-materialized). The default 3-tier recall carries **zero** re-rank cost.
- **Index size/cost ceiling:** descriptors only (no bodies) keep the index small — estimated low-single-digit MB at 20 shared projects. Hard guard: refuse to index a single entry's postings beyond a bounded vocab cap; warn (don't crash) if `doc_count` crosses the sharding threshold.
- **Degradation (must be silent, per posture):** no shared corpus + no verdicts → "no cross-project knowledge yet" + current-project recall; no `claude` CLI / re-rank disabled / timeout → Stage-1 BM25 ordering; index missing/corrupt → recall behaves as today (feature simply absent); secret-scan uncertain → redact (fail closed). Every failure path returns useful output, never throws.

## 9. LOCKED — MVP scope boundary (what unblocks A5) and explicit non-goals

### Minimum-viable F4 (the A5-unblocking core) — IN

## 13. One-paragraph executive summary

F4 v5.0 MVP is a **dep-free, offline, pure-Node BM25 cross-project knowledge index** over PRISM's adjudications (incl. `/prism-clean` artifacts), lessons, plans, panel-rationales, and always-on home-global verdict logs — with **mandatory project-provenance tags** and a **default-deny, per-corpus-type privacy model** (`.prism-kb-share.json` lists which types a project shares; explicit `--cross-project` consumption; descriptors-not-bodies storage; conservative secret pre-scan). On top of the BM25 base sits a **default-on `claude -p` LLM re-rank** (the human-locked "semantic" layer — NOT embeddings) that is bounded to top-K body-free descriptors, capped by an 8s timeout, and **degrades silently to BM25 ordering** whenever the CLI is absent/slow/erroring, so "required" never means "hard dependency." It coexists with (does not migrate) the existing resource-descriptor index, reuses the autosync dirty-flag and E1 freshness seam, ships single-machine with a sync-compatible layout, and exposes a stable `queryKnowledge({crossProject, limit, rerank})` API that unblocks A5. Vector embeddings are deferred (not foreclosed — a clean pluggable seam remains). All five human open questions are closed (§12); design is locked for build.
