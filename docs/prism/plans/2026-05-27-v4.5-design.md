# v4.5 design — telemetry tooling + OOB completion + installer hardening + coverage picks

**Status:** Draft
**Date:** 2026-05-27
**Captured by:** /superpowers:brainstorming session
**Related:** [[2026-05-27-v4.4-installer-pending-v5-handoff]] [[2026-05-26-v4.4-phase-1-5-oob-reviewer-design]] [[2026-05-26-v4.4-implementation-plan]] [[feedback-prism-claude-p-auth-pattern]] [[feedback-cross-phase-review-pattern]] [[feedback-installer-architecture-pattern]] [[feedback-handoff-backlog-reverify]]

## One-sentence summary

v4.5 closes 15 of the 28 v4.5/v4.6 candidates documented in the v4.4 ship handoff, across four composing layers (telemetry-data-collection tooling without calibration decisions; OOB completion finishing the Phase 1.5 LITE plumbing and adding a Phase 0d panel-side reviewer; installer hardening with `--purge-state`, `update` subcommand, expanded backup paths, and a `--target <dir>` flag that turns the existing `competition_agents/` testbed into a reproducible install/upgrade harness; and two coverage/hygiene picks — SCOPE GUARD enforcement test and alternatives-considered logging) — leaving telemetry-driven calibration decisions, structured-output classifiers, and the harder coverage items for v4.6 once v4.5 produces production telemetry data.

## Motivation

v4.4 shipped two distinct deliverables: the OOB Phase 1.5 reviewer (PR #2) and the installer (PR #3, merged 2026-05-27). The original v4.4 brainstorm spec called out 18 deferred gaps split into 13 v4.5 candidates and 5 v5.0 candidates; cross-phase review then surfaced ~10 new candidates (OOB completion, verdict-log polish, installer polish), giving us 28 total candidates for the next minor release. The handoff frames v4.5 as "telemetry-driven calibration + OOB completion + installer polish + 2 from coverage/hygiene" — but the user has chosen to defer first install until v5 ships, which means **no v4.4 production telemetry data will exist when v4.5 is being built**.

This spec resolves the resulting paradox by **scoping Layer 1 (telemetry) to tooling only**: build the data-collection hooks and the aggregator, but defer all calibration decisions (B1 cap retune, master-overrides confirmation gate, auto-clear pending_upgrade thresholds) to v4.6 once v4.5 has been installed and has produced 30+ days of data. The remaining three layers focus on completing the OOB reviewer surface (Layer 2 — largest), hardening the installer for first real install (Layer 3), and a tight coverage/hygiene pair (Layer 4).

Cut: **15 items** across **4 layers**, ~7d implementation effort, ~5.5d wall-clock with parallel execution. Mirrors v4.4 cadence.

## Scope: the 15 items

### Layer 1 — Telemetry tooling (3 items, ~1.5d)

| 2 | **B3-tool** parallel-dispatch cap measurement | Hook fires at master's parallel dispatch points, logs `{event:"dispatch_cap", cap, actual_parallel, queue_depth}`. No retune; just data. |

**Layer 1 invariant:** zero default-value changes. v4.6 reads the aggregator output and decides retunes.

### Layer 2 — OOB completion (6 items, ~3.5d — LARGEST LAYER)

| # | Item | Brief |
|---|---|---|
| 4 | **A1** Phase 0d panel-side OOB reviewer | NEW hook `hooks/prism-phase-0d-oob.mjs` mirrors v4.4's `prism-phase-1-5-oob.mjs`. | 6 | **O2** roster.json parallel-session safety | Add `tools/lib/prism-roster-lock.mjs` providing read-modify-write helper using exclusive-create lock file (`roster.json.lock`) with 30s timeout. | 7 | **O3** flagged-path SessionStart pickup E2E test | New test `tests/v3/state/test-oob-pickup-e2e.mjs` simulates: hook writes verdict file → SessionStart hook fires → additionalContext emitted with correct severity filter. Closes a real testing gap from v4.4. |

| 9 | **A3** DROPPED-verdict logging in panel.json | `hooks/prism-panel-guard.mjs` patch: when a panel position is dropped (insufficient challenges, EVIDENCE missing, etc.), append `{position, reason, dropped_at_phase}` to `panel.json.dropped_positions[]`. Closes the v4.5-A3 bias gap. |

**Layer 2 risk note:** A1 is the largest single item. Mitigation strategy: A1 is structurally a copy-paste of `hooks/prism-phase-1-5-oob.mjs` with file path and prompt swapped — same `claude -p` invocation, same `tools/lib/prism-verdict-flag.mjs` lib, same SessionStart pickup pattern. If A1 does NOT factor cleanly as a copy, descope it to v4.6 at the Phase 2 review checkpoint.

### Layer 3 — Installer polish (4 items, ~1.5d)

| # | Item | Brief |
|---|---|---|
| 10 | **I4** `--purge-state` flag for `uninstall` | Cleaner UX than the absent-but-discussed `--keep-state`. `uninstall --purge-state` wipes roster.json, verdict logs, routing log, MEMORY.md. Default uninstall preserves state for re-install. |
| 11 | **I5** expanded backup paths in manifest | Current backup captures settings.json + roster.json. Expand to also capture every file the installer writes (per `install-manifest.json.files`) plus user-modified hooks/agents/tools detected via SHA-mismatch. Enables true rollback. |
| 12 | **I6** `update` subcommand | `prism-installer.mjs update` chains `detect → backup → install` with idempotency checks. Today users run `install` over an existing install, which works but lacks ergonomic safety. `update` adds version-check messaging and a dry-run flag. |
| 13 | **I7** `--target <dir>` flag | All installer subcommands accept `--target <path-to-.claude>` to override the default `~/.claude/` resolution. Enables installing into `competition_agents/.claude/` for behavioral testing without polluting laptop user-global state. Single helper `resolveTarget(cliArg)` threaded through all manifest pipes. |

### Dispatch topology (post-v4.5)

```
master-<slug>  ← Phase 0d ends, panel.json written
       │
       ▼ PostToolUse hook event (NEW in v4.5)
  prism-phase-0d-oob.mjs  (Layer 2, item #4 / A1)
       │  reads panel.json + transcript window
       │  spawns claude -p with phase-0d-oob-reviewer.md prompt
       │  acquires roster-lock (Layer 2, item #6 / O2)
       │
       ▼ writes ~/.claude/.prism-phase-0d-verdicts-<sha>.json
       │
       ▼ SessionStart pickup (existing v4.4 path; no changes)
       │
       ▼ additionalContext → master sees panel-quality verdict
       │
       ▼ if REJECTED → master must reopen Phase 0d

(Existing v4.4 Phase 1.5 OOB topology unchanged, except OOB hook now reads
 roster.<spec>.phase_1_5_lite_oob for shorter prompt (item #5 / O1).)
```

### Key design choices

| Choice | Decision | Rationale |
|---|---|---|
| A1 firing trigger | PostToolUse matching `Write` to panel.json path glob | panel.json is the durable artifact of Phase 0d's end; no other event marks the boundary cleanly |
| A1 prompt source | `agents/phase-0d-oob-reviewer.md` (NEW), separate from `phase-1-5-oob-reviewer.md` | Different evaluation criteria (panel quality vs verdict quality); separate prompts avoid prompt-conflation drift |
| O2 lock mechanism | Exclusive-create `.lock` file with 30s timeout + stale-lock detection | Cross-platform (no native flock); matches existing atomic-write idioms in `tools/lib/prism-flag-file.mjs` |
| Telemetry schema versioning | Additive-only changes; bump `.prism-routing.jsonl` `schema_version` field from 2 → 3. **Semantic:** schema_version is the *writer's version*, not a minimum-reader requirement. Readers MUST treat unknown fields as benign and accept entries with higher schema_version than they were built for. v4.4 readers will silently ignore the new `phase_0d_challenge` + `dispatch_cap` event types. | Existing consumers (aggregator, drift-guard) treat unknown fields as benign |
| Installer `--target` resolution | Single `resolveTarget(cliArg) → absolute path` helper at top of installer; all manifest pipes call it | Avoids grep-and-replace of `os.homedir()` calls across the file |
| `update` semantics | `update` = `detect && backup && install` (chained, with stop-on-detect-version-equal) | Idempotent; safer than naked `install` on existing install |
| Items NOT shipping | Items in §"Deferred to v4.6" — surfaced explicitly so review knows what's missing | Closes the cross-phase-review false-omission pattern from `[[feedback-cross-phase-review-pattern]]` |

## Data flow

1. **Layer 1 → Layer 1 aggregator:** `phase-0d-challenges.mjs` + `dispatch-cap.mjs` write JSONL events → `prism-telemetry-aggregate.mjs --agreement` reads + joins by task_sha + emits agreement-rate report. Pure read-only consumer chain.
2. **Layer 2 A1 (Phase 0d) → SessionStart:** `prism-phase-0d-oob.mjs` writes verdict file in same format as Phase 1.5 verdicts → existing `hooks/prism-session-start.mjs` pickup function consumes both verdict types via shared file-glob. No SessionStart code changes.
3. **Layer 2 A1 ↔ Layer 4 G2:** A1 reviewer reads `panel.json.rationale.alternatives_considered` (Layer 4) to judge whether the master genuinely considered options. Layer 4 produces what Layer 2 consumes.
4. **Layer 2 O2 (roster-lock) ↔ all roster-mutating callers:** roster.json read-modify-write paths in `prism-roster.mjs`, `prism-phase-1-5-oob.mjs`, `prism-phase-0d-oob.mjs` all wrap their mutations in `withRosterLock(async () => { ... })`. Lock file is `<roster.json>.lock` adjacent to the file.
5. **Layer 3 I7 `--target` ↔ all installer subcommands:** `resolveTarget(opts.target ?? os.homedir() + '/.claude')` returns the resolved absolute path; threaded into manifest pipes, backup paths, settings.json read/write, lock paths. Single point of change.

## Error handling

| Surface | Failure mode | Behavior |
|---|---|---|
| A1 (`prism-phase-0d-oob.mjs`) | `claude -p` returns non-zero or times out | Mirror v4.4 Phase 1.5 OOB: log to stderr, write verdict file with `severity: "ERROR"` + error body; SessionStart surfaces as ERROR. Does NOT block master. |
| A1 hook itself crashes | Uncaught exception | Hook exits non-zero; Claude Code logs to its hook-error path; master continues. Same posture as v4.4 OOB. |
| O2 lock contention | Another process holds lock | Wait up to 30s with exponential backoff; on timeout, log loud warning + skip the lock (proceed with read-modify-write race-prone path). Loud warning means user sees it; staleness recovers on next call. |
| O2 stale lock | Lock file exists but PID unreachable | Detected via stored PID + creation time; auto-removed after 60s threshold. |
| Installer `--target invalid` | Path doesn't exist or isn't writable | `die(2, "Target dir does not exist or is not writable: <path>. Create it first or correct the path.")` |
| Installer `update` on already-current | Detect reports installed_version == target_version | Emit `"Already at vX.Y.Z; nothing to do."` and exit 0. No backup, no writes. |
| Installer `--purge-state` confirm | User did not pass `--yes` | Prompt `"This will delete roster.json + verdict logs + MEMORY.md. Continue? [y/N]"`; default N. |
| Telemetry hook crashes | Logging fails (disk full, permission) | Catch + emit stderr warning; do NOT throw. Telemetry is non-critical; never block dispatch on logging failure. |

## Testing strategy

Unit + integration + manual smoke, matching v4.4:

**Unit / state tests (~50 new):** Each new lib / hook gets its own test file with mocks for `claude -p` (spawnSync mock returning canned JSON) and `roster.json` (in-memory). Target: existing 310/310 + ~50 new = ~360/360.

**E2E test (1 file, item #7 / O3):** `tests/v3/state/test-oob-pickup-e2e.mjs` exercises the full verdict → SessionStart pickup → additionalContext path with real file I/O against `~/.claude/.prism-test-<uuid>/` temp dir.

**Behavioral smoke (manual, against `competition_agents/`):** After Layer 3 ships, install v4.5 into `competition_agents/.claude/` via:
```bash
node tools/prism-installer.mjs install --target Y:/Documents/utilities_projects/competition_agents/.claude
```
Then `cd Y:/Documents/utilities_projects/competition_agents && claude` and run a FULL-NOVEL prompt. Verify:
- Phase 0d panel.json appears with `dropped_positions[]` + `rationale.alternatives_considered[]` (Layer 4 working)
- `~/.claude/.prism-phase-0d-verdicts-<sha>.json` appears within 10-15s of panel.json (Layer 2 A1 working)
- Next-turn additionalContext surfaces the verdict (existing SessionStart pickup)
- `.prism-routing.jsonl` contains new `phase_0d_challenge` + `dispatch_cap` events (Layer 1 working)
- Phase 1.5 reviewer for any FULL-ROUTINE spec uses LITE prompt (Layer 2 O1 working)

**Cross-phase review (per `[[feedback-cross-phase-review-pattern]]`):** After all 4 layers ship + per-layer reviewers pass, dispatch one final cross-phase reviewer agent that compares the spec against the shipped diff for: (1) doc-drift between layers (false claims about what each layer does); (2) silent inversions (a layer's invariant violated by another layer); (3) deferred-items list freshness.

## Risks and scope guards

| ID | Risk | Likelihood | Mitigation |
|---|---|---|---|
| R1 | **A1 doesn't factor as a copy of v4.4 OOB hook** — diverging needs around panel.json vs verdict reading | Medium | At Phase 2 review checkpoint, if A1 LOC > 350 or test file > 280 LOC, descope A1 to v4.6 and ship v4.5 with 14 items. |
| R2 | **O2 cross-platform lock** — Windows lock semantics differ from POSIX | Medium | Use exclusive-create `.lock` file (not native flock). Tested on Win11 + macOS in CI matrix. |
| R3 | **`--target` flag breakage of existing default-path behavior** | Low | Single `resolveTarget()` helper at top of installer; default-path tests verify `--target` omitted = `~/.claude/` resolution unchanged. |
| R4 | **Schema drift in `.prism-routing.jsonl`** — bump 2 → 3 breaks v4.4 consumers | Low | Additive-only field changes; v4.4 consumers ignore unknown fields. Schema version bump is documentation-only. |
| R5 | **Telemetry hooks add latency on master's hot path** | Low | All telemetry hooks are fire-and-forget JSONL append; <1ms typical. Measured in O3 E2E. |
| R6 | **competition_agents/ testbed has unexpected v3.11.0 cruft** that breaks `--target` install | Medium | Before first `--target` install, run `node tools/prism-installer.mjs detect --target <path>` and review report; if blockers found, treat as installer bug + fix before tagging v4.5. |
